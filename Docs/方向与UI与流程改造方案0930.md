# 方向一致性 / UI 摆放 / 游戏流程 改造方案（0930）

## 一、转场方向一致性

### 现状（全量审计结果）
相机俯角 50°、yaw=0：屏幕上=+Z（北），屏幕右=+X（东）。街道链 7 对转场中 4 对非镜像，详见下表"目标"列即修法。

### 统一约定
1. **前进（东向）一律"右出左进"**：从区域东墙门出 → 在下一区域西侧出生点出现。
2. **返回（西向）一律"左出右进"**：从西墙门出 → 在上一区域**东侧**出生点出现（即镜像）。
3. **室内门**：出口保持现状（全部南墙、落在门外，已统一）；进门落点统一为"**深侧**"（门在背后，符合走进房间的直觉）。
4. spawn 命名统一为 `from_<区域ID>`，废弃裸名（`bar`/`financial` 等保留为地图传送 default 用）。

### 具体修改（全部在 DetectiveRegionBuilder.cs，改完跑 Build Core And Regions + Validate NavMesh）

| 修改点 | 现状 | 改为 |
|---|---|---|
| D2.Exit_West → D1 | targetSpawn `financial`（西侧 -19,0） | `from_D2_Financial`（东侧 19,0，已存在未被引用） |
| D3.Exit_West → D2 | targetSpawn `industrial`（西侧 -22,0） | 在 D2 东侧新增 `from_D3_Industrial`（约 22,0） |
| D2.Exit_East → D3 | 落 `from_D2_Financial`（D3 东侧 20,0） | D3 西侧新增落点（约 -21,0），或把该 spawn 移到西侧 |
| D4.Exit_West → D3 | targetSpawn `residential`（**不存在的 ID，静默 fallback**） | `from_D4_Residential`（东侧 20,0，已存在未被引用） |
| 酒吧/仓库/你家/死者家 进门落点 | 近侧（北半） | 深侧（南半、门在背后），与公寓/咖啡店/地下室一致 |

注意：地图传送（DetectiveMapUI）走 `Spawn_default`，不要动 default 的位置；只改门引用的 targetSpawnId。

### 顺带确认
- D1 没有回 D0 的门（序章单向）——设计确认后如需返程另补。
- 两场对决的大红环（直径 9/5）在方向统一后复核观感。

## 二、UI 从"代码生成"改为"编辑器摆放"

### 现状问题
- 全部 UI 由 `DetectiveCityBuilder.BuildSceneUI`（:652）代码生成，坐标硬编码；
- "Rebuild Scene UI" 菜单只作用于**已弃用的** DetectiveCity.unity；Core.unity 的 UI 由 "Build Core And Regions" 每次全量重建覆盖——两条路径互不同步，且任何手工调整都会在重建时丢失。

### 改造方案
1. **拆分生成与重建**：`BuildCoreAndRegions` 拆成两个菜单：
   - `Detective/Build Regions`（只重建 13 个区域场景，**不碰 Core**）；
   - `Detective/Build Core Scene`（只在 Core.unity 不存在或 UICanvas 缺失时生成完整 Core；已存在则跳过 UI 部分，只更新 Systems/Loader 等逻辑对象）。
2. **一次生成、之后手摆**：现在跑一次生成拿到代码版布局作为底稿，之后所有 UI 调整（位置、字号、排版）直接在编辑器里改 Core.unity，代码不再覆盖。`BuildSceneUI` 的各 Build 方法保留为"初始化脚手架"，加 `if (existing != null) return;` 保护。
3. **废弃 "Rebuild Scene UI"**（或改为作用于 Core.unity），删除 DetectiveCity.unity 相关路径，消除双轨。
4. **对决按钮接线**：在 Core 场景的 DuelPanel 里手工摆好【追问】【跳过本轮】按钮并接到 `DetectiveDuelRunner.pressButton/skipButton` 序列化字段，删除 `EnsureAuxButton` 运行时代码兜底。
5.  endings/对话/思维面板等运行时需要动态实例化的部分（选项按钮、手牌卡）保留模板+clone 模式，但模板 prefab 在编辑器里摆好，不在代码里 new。

### 预期收益
UI 布局改动不再需要改代码+全量重建，策划/美术直接调；Builder 代码不再握有布局字面量。

## 三、游戏流程补全（开始菜单 / 暂停菜单 / 结局后流程）

### 现状
- 无标题界面：Build Settings 第 0 场景 Core，首帧直接加载小巷开局。
- 无暂停菜单：全库无 Esc/暂停逻辑。
- 结局结算后是死胡同：无重开/回菜单；`DetectiveGameState.ResetAll()` 存在但无调用者；时间到 06:00 自动进结局 E。

### 方案（全部 UI 在 Core.unity 编辑器里摆好，符合第二节原则）

**1. 开始菜单（TitlePanel，Core 场景）**
- 内容：游戏标题 + 【开始调查】【操作说明】【退出】。
- 流程改造：`DetectiveRegionLoader.Start()` 不再自动 `LoadRegion("D0_Alley")`，改为等待 TitlePanel 的"开始"按钮回调再加载。期间相机对准一个静态背景（可用小巷场景预加载后镜头固定，或简单黑底+标题）。
- 【退出】`Application.Quit()`。

**2. 暂停菜单（PausePanel，Core 场景）**
- Esc 开合；游戏时间本就由剧情节点驱动，无需 timeScale，只需 `InteractionController.DialogueBlock = true` 锁交互（复用现有机制）。
- 按钮：【继续】【操作说明】【回到标题】。
- 【回到标题】：`DetectiveGameState.ResetAll()` → 卸载所有区域场景 → `SceneManager.LoadScene("Core")` 完整重启（最干净，避免状态残留）。

**3. 结局后流程（EndingPanel 扩展）**
- 结算面板底部加两个按钮：【再次调查】（= ResetAll + 重载 Core，直接进开局）、【回到标题】。
- 各结局差异化呈现（数据驱动，已有资产结构上加字段即可）：
  - `DetectiveEndingDefinition` 增加 `bgm/背景色调/结局标题` 字段；A 日出暖色、B 警灯蓝红、C 雨夜冷灰、D 雨夜+血红压暗、E 灰白。
  - 结算文案已按结局区分（0930 已落实），只需 UI 上把结局名+色调做出来。
- `DetectiveEndingUI.Advance()` 在 `settlementShown` 后改为激活按钮组而非直接 return。

### 新增/改动文件预估
| 文件 | 改动 |
|---|---|
| DetectiveRegionBuilder.cs | 拆菜单、Core 跳过已有 UI、spawn/门修正（第一节） |
| DetectiveCityBuilder.cs | BuildSceneUI 各方法加存在性保护；删 Rebuild Scene UI 旧路径 |
| DetectiveRegionLoader.cs | Start 不自动加载，等标题回调 |
| DetectiveEndingUI.cs | 结算后按钮组 + 结局色调 |
| DetectiveEndingDefinition.cs | 加标题/色调字段（5 个结局资产同步） |
| DetectiveGameState.cs | 无需改（ResetAll 现成） |
| 新增 DetectiveTitleMenu.cs / DetectivePauseMenu.cs | 两个面板控制脚本 |
| Core.unity | 编辑器里摆 TitlePanel/PausePanel/对决按钮，保存 |

### 建议实施顺序
1. 方向一致性修正（纯数据，风险最低，先修）→ 重建 + Validate NavMesh + 实机走一遍五区往返。
2. UI 双轨拆分（Build Regions / Build Core Scene）→ 之后 UI 全部编辑器手摆。
3. 对决按钮接线。
4. 开始菜单 → 暂停菜单 → 结局后按钮（依赖 2 的 Core 保护，否则重建会被覆盖）。
