## 四、对决系统改造（逆转裁判式）——数据结构要求

现状：`DuelEntry` = 一句 `OpponentThesis` + 严格顺序 `RequiredSequence` + `StepReplies` + 全局 `WrongCards`。
目标：**证词列表驱动**，每句证词独立判定，错误不锁进度。

新增结构（`DetectiveContentData.DuelEntry` 扩展，`DetectiveDuelDefinition` 加对应序列化字段）：

```
DuelStatement {
  string text;                    // 证词原文（辩台大字显示，可含【高亮】标记）
  string phaseLabel;              // 阶段名，如"第一阶段·你怀疑他"（空=不显示）
  PopupEntry[] pressHints;        // “追问”时四声音提示（免费）
  CardReaction[] reactions;       // 本句证词的出牌反应表
  string skipReply;               // 正确牌不在手时“跳过本轮”的对方台词（空=不允许跳过）
}
CardReaction {
  string clueId;                  // 出的牌
  string reply;                   // 对方反应台词
  bool advance;                   // 是否击破本证词
  int focusDelta;                 // 专注力变化（错误牌为负）
  VoiceDeltaEntry[] voiceChanges; // 声音增减
  string setFlag;                 // 出牌成功置 flag（结局牌用）
  string requireVoice; int requireVoiceLevel; // 出牌门槛（结局牌用）
  string[] requireClues;          // 需同时持有的线索（D 结局三件套）
  string lockedReply;             // 门槛/条件不满足时的提示（如"你的脑子转不到那一步"）
}
```

Runner 行为（`DetectiveDuelRunner` 改造）：
1. 逐句显示当前证词（阶段标签变化时显示阶段标题演出）。
2. 【追问】按钮：免费，显示 pressHints 四条心声。
3. 【出牌】：查当前证词 reactions 表 → 命中按表执行；未命中走通用错误（专注力-10，通用反驳"这能说明什么？"，计 1 次失误）。
4. advance=true → 进入下一句；全部击破 → WinDuel。
5. setFlag 非空 → 置 flag 并立即结束对决（结局牌）。
6. 正确牌不在手且 skipReply 非空 → 提供【跳过本轮】按钮（专注力-10，计 1 次断链）。
7. 失误/断链合计 ≥ MaxMistakes → FailDuel。
8. 旧字段（OpponentThesis/RequiredSequence/StepReplies/WrongCards）废弃，两场对决全部迁移到新结构。
