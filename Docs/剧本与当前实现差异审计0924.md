本文件保留审计时的历史状态。后续用户已授权整合；当前实现与验证请看《剧情交互整合验收0924.md》，不要将下表当作最新未完成清单。

## 核对口径

- 基线：《项目3游戏剧情0920修订版.md》；冲突按《项目3剧情0930实施规格.md》裁决，再叠加本任务内用户后续试玩要求。
- 核对了运行时代码、内容生成表、对白/配方资源，以及 Unity 中保险箱和玩家公寓的实际配置。钥匙做了 Play Mode 验证。其余是静态及配置审计，不是每个分支的完整人工通关。
- 仓库未找到编剧《项目3游戏剧情修改版(1)》的独立原文，本次对该版本的判断限于0930合并规格和已有开发记录，不声称覆盖未提供的原稿。
- 不能把所有差异称为“为了逻辑连贯而省略”。有明确版本裁决、有交互简化、有实际缺陷，也有尚未制作的灰盒演出；没有记录的原因不臆测。

## 本次已补：掉落钥匙与工业区铁门

1. 未拿钥匙检查铁门：只得到“铁门已被撬开、锁孔有新划痕”，不会凭空判断钥匙吻合。
2. 持有钥匙检查铁门：核对锁芯匹配，记录推理结果。门已经被撬开，不再设置强制开门条件。
3. 先查铁门、后拿钥匙：铁门重新可核对，黄圈重新提示；核对完成后消失。也可直接在思维面板组合【掉落的钥匙】与【铁门：被撬开】。
4. 结论只说明风衣男持有这里的钥匙，不直接断言他撬门或实施凶案。
5. 不增加物证条数，不消耗钥匙，不额外奖励声音；重复组合可回看但不会刷奖励。

验证：两种取得顺序均通过，未持钥匙不产生结论；核对不重复发铁门线索；结果页可见；双卡正反顺序匹配。Console 无 error/warning。恢复 Core 编辑模式。
